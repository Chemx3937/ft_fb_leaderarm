## 변경

- 새 계획은 점증 가압·해제 공통20회다. 추가 weak/normal 수집은 비활성화하고
  과거 raw·trial snapshot·FREE20 결과는 보존한다. 모델·controller·zero·잔차
  ON/OFF3.0/1.2N·hold20/20ms는 유지한다.
- `LiveTraceWriter`는 실제 계산 callback마다 입력·예측·잔차·준비·판정·시각을
  bounded queue에 넣는다. 별도 writer가 저장하고 누락·쓰기 오류·SHA를 보고한다.
  첫 checkpoint에서 pending hold를 보존하고 원본 재계산으로 대체하지 않는다.
- 외부 센서는 계산 완료 시각 직전3ms 이내의 원본 하중을 대응시키는 데 사용한다.
  외부 CONTACT 문턱을 제거하고 사전 활성·상한 후 검출·미검출·동기 불량을 분리한다.
- 기준 검사는 detector 클래스를 다시 사용하지 않고 threshold/hold를 별도 계산한다.
  고의적인 조기 CONTACT·잔차 변조를 검출하고 짧은 pulse·히스테리시스·수집 직전
  pending hold·DUPLICATE 전후의 실제 전환을 검사한다.
- 초기·최종 실제 무접촉은 운용자 절차다. 외부 무부하 노이즈 범위는 최종3초
  자동 안내만 돕고 검출 인정 여부에 사용하지 않는다. 모델 미검출·기준 위반은
  정상 수집한20회에서 제외하지 않는다.

- 사용자에게 같은 zero-set·센서·박스 파지를 유지 중임을 확인받았다.
- 과거 pilot30초로 실제 모델을 계산하는 소프트웨어 모의 검사를 실행했다.

## 검증 중 실패와 보완

- 처음 두 테스트는 실시간 module 미구현으로 실패한 뒤 구현 후 통과했다.
- 분석 경로를 연결하면서 기존 weak 테스트의 mock session을 불필요하게 읽어
  두 항목이 실패했다. 새 session 분기는 ramp에만 적용해 회귀를 해결했다.
- sandbox의 ROS 기본 log 경로·Chrony socket 접근이 막혀 읽기 조회가 실패했다.
  ROS log는 임시 경로를 사용하고 graph/Chrony 읽기만 sandbox 밖에서 수행했다.
- 마지막 diff 검사를 git 저장소가 아닌 workspace 부모에서 호출해 경로 검사가
  실패했다. 저장소 경로에서 다시 실행해 통과했으며 빌드·테스트는 별도로 확인했다.
- 실제 세션의 외부 하중 banner가 두 줄로 잘리는 것을 보고 새 mode의 중복 상한
  줄을 제거했다. 세 모델 표와 외부 하중 표시를 다시 확인했다.
- DUPLICATE가 직전 tick에 있으면 첫 실제 전환을 놓칠 수 있어 checkpoint와
  상태 보존·reset 규칙으로 전환을 추적한다. 시작 tick에 FREE로 돌아온 경우도
  사전 CONTACT로 잘못 제외하지 않도록 회귀 검사를 추가했다.
