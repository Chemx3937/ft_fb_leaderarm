# FT-20261110-02: PC Chrony 서비스 중지로 gene 동기화 조회 실패

- 상태: CLOSED
- 분류: SYNC
- 누가: PC `vision`의 Chrony client와 `chrony.service`
- 언제: 2026-11-10 KST, 세 모델 비교 실험 전 시간 동기화 복구 중
- 어디서: PC의 `dualarm_chrony_mode.sh off`, `chronyc sources -n`
- 무엇을: `ERROR: failed to query the current Chrony source state`로 종료됐다.
- 왜: 호스트에서 `chrony.service`가 `inactive (dead)`이고 chronyd 프로세스가
  없었다. `chronyc`는 `506 Cannot talk to daemon`을 반환했다.
- 어떻게: 스크립트의 `source_marker()` 호출과 실제 호스트의 service status,
  journal, Chrony source 조회를 대조했다. 로그에는 2026-11-07 16:40 KST의
  정상 종료가 있으며, 누가 또는 무엇이 종료했는지는 확정하지 않았다.

## 확인과 복구

- 최초의 `No such file or directory`는 홈 디렉터리에서 상대 경로로 실행한
  별도 실행 위치 문제였다. 올바른 경로 및 기존 alias로 실행한 뒤에도
  source 조회가 실패해 daemon 상태를 확인했다.
- `off`의 첫 source 조회에서 반환했으므로 해당 시도는 소스 삭제나 SBC ACL
  변경 단계까지 진행되지 않았다. stderr를 숨기는 호출이지만 조회 실패 시
  중단하는 동작은 유지한다.
- 초기 sandbox 조회는 호스트 socket/system bus에 접근하지 못했다.
  읽기 전용 호스트 조회로 재확인해 실제 daemon 중지를 확인했다.
- 에이전트의 `sudo -n systemctl start chrony`는 sudo 인증 부재로 실패했다.
  운용자가 PC 터미널에서 아래 한 줄을 실행해 `active`를 확인했다.

```bash
sudo systemctl start chrony && systemctl is-active chrony && chronyc -n sources
```

- 재확인 시 PC는 public NTP `211.108.117.211`을 선택했고 Leap status는
  `Normal`이었다. gene `192.168.112.17`도 service `active` 및 Leap status
  `Normal`이었다. 양쪽이 외부 NTP와 동기화됐다는 사실은 PC/gene 상대 오차
  `<= 1 ms` 통과 evidence가 아니다.
- runtime ON marker는 없었으며 PC source에 gene도 없었다. 운용자에게 기존
  `dualarm_time_off && dualarm_time_on && dualarm_time_status` 실행을 요청했다.
- 제어 코드, 영구 Chrony 설정과 서비스 enable 설정은 수정하지 않았다.
  로봇 동작, FT zero-set, 실험 수집도 실행하지 않았다.

## 재검증 기준

- `chronyc sources -n`에서 gene `192.168.112.17`이 `^*`로 선택된다.
- `on`의 direct relative bound `<= 1.0 ms`와 `status`의 내부 상태·SBC ACL
  검사가 모두 GO다. 이것을 확인하기 전에는 실험용 시간 동기화 완료로 기록하지
  않는다.

## 완료 검증

- 2026-11-10 KST 운용자가 제공한 `off && on && status` 전체 출력으로 확인했다.
  OFF public NTP 복구, ON 상대 오차 검사, 최종 status가 모두 GO였다.
- 선택 소스는 `^* 192.168.112.17`, Reach는 `377`, valid NTP sample은
  `10`개였다. PC와 gene의 Leap status도 모두 `Normal`이었다.
- direct relative error bound는 `0.0400925 ms`로 기준 `1.0 ms` 이내다.
  측정 absolute offset은 `0.007259 ms`다. 이 상대 검증은 UTC에 대한
  절대 정확도 보장으로 해석하지 않는다.
- ON marker가 존재하고 최종 SBC ACL은 `208 Access allowed`였다.
  중간 `209 Access denied`는 OFF/ON 전환 중 접근 차단 상태를 확인한 응답이며,
  초기 convergence 대기는 유효 sample 확보 뒤 통과했다.
- Evidence: session의 `chrony_recovery_20261110.json`에 운용자 출력의
  검증 수치와 최종 상태를 보존했다. 상태 `CLOSED`는 이번 시간 동기화 복구에
  한정하며 핸드 파지, FT 기준 확인이나 전체 실험 준비의 완료를 뜻하지 않는다.
