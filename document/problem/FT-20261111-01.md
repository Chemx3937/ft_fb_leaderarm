# FT-20261111-01: 비교 세션의 정지 검사 누락과 teleop 제어 루프 지연

- 상태: OPEN
- 분류: OPS/RUNTIME/ROBOT
- 누가: 운용자의 오른팔 리더암 feedback OFF 무접촉 비교 실험
- 언제: 2026-11-11 KST, 두 번째 zero-set의 5회 기록
- 어디서: `data/three_model_comparison/session_20261111_02/`
- 무엇을: 사전 정지 노이즈 검사가 없고, 운용자가 2~4회차 중 정지 후 갑작스런
  이동을 보고했다. 모든 원본의 모델 입력 유효 표본 수는 15,750개였다.
- 왜: 정지 검사 누락은 GUI가 안내만 하고 시작을 차단하지 않은 결함이다.
  이동 이상은 3회차의 긴 제어 루프 간격 및 로봇 속도 변화와 일치한다.
  PC 처리, 통신, 로그 I/O 등 중 정확한 지연 원인은 확정하지 않았다.
- 어떻게: raw robot q/dq, 저장 예측 NPZ, leader CSV의 `t_s`와 `dt_ms`를 대조했다.

## 관측

- zero ID: `comparison_20261111_02_wrist_tare_02`.
- 누락된 정지 검사 대신 첫 10초를 검토했지만, 각 기록의 그 구간에는 기준 자세
  오차가 약 2.4~5.5 deg이고 미세 움직임도 있다. 센서 노이즈 검증 PASS로
  소급하지 않는다. 60초 전체에서도 기준 자세·정지 조건을 동시에 만족하는
  1초 구간을 찾지 못했다. 이는 실제 zero-set 자세가 잘못됐다는 증거는 아니다.
- 해당 3회차는 `20261111_010837_047332_free`, GUI 누적 번호는 8이다.
  score 시작 후 약 9.774→10.642, 14.363→15.875, 17.312→18.345초에
  제어 로그 간격이 각각 0.868/1.512/1.033초였다.
- 마지막 간격 말미의 관절 속도 중앙값은 약 0.0175 rad/s, 이후 0.7초의
  최대 관절 속도는 약 0.999 rad/s였다. 운용자 보고와 강하게 일치한다.
- 다른 회차에도 약 30~104 ms 간격이 관측됐다. 무효 표본 0이나 오검출 0을
  teleop timing 정상의 증거로 해석하지 않는다.

## 처리와 남은 확인

- 모델 오차가 크다는 이유로 구간만 자르지 않고 해당 3회차 전체를 주 비교에서
  제외한다. 원본은 `excluded_trials/`에 보존하고 robustness 진단용으로 남긴다.
- 나머지 4회는 보존하고 아래 사후 정지 검사로 zero 품질 evidence를 보완했다.
- 운용자는 동일 zero·장착·파지가 유지된다고 확인했다. 새 zero 없이 기준 자세에서
  10초 정지 검사를 보완할 수 있다. 사후 측정은 사전 검사와 구분해서 기록한다.
- 2026-11-11 운용자가 `20261111_012648_304801_noise`를 추가 수집했다.
  양쪽 센서 각 10,000개, 자세 최대 오차 0.1442 deg, 최대 관절 속도
  0.01230 rad/s, 손목/state header 차이 최대 1.4963 ms를 raw에서 확인했다.
  저장된 noise 통계와 재계산이 일치하고 정지 zero gate는 PASS다.
  `supplementary_noise_validation.json`에 사후 측정임을 명시했다.
  사전 검사 누락을 소급해 PASS로 바꾸지 않는다.
- GUI는 이 zero ID의 PASS 정지 기록이 없으면 본 실험 시작을 차단하도록 수정한다.
  실제 장비의 정지 검사는 위 운용자 기록으로 보완했다.
- 이후 운용자는 teleop 지연을 수정하지 않고 대체 1회를 진행하도록 요청했다.
  `20261111_013151_531465_free`는 60초·공통 유효 15,750개·무효/재준비 0개,
  세 모델 오검출 0회로 저장됐고 제외 회차를 대체했다. 두 번째 세션의 선택 기록
  5회 집계는 `free_five_trial_summary.json`이다. 이 수치는 제어 지연 해결이나
  최초 4회의 사전 zero 검사 통과를 뜻하지 않는다. 제어 코드는 변경하지 않았다.
- 지연 원인이 아직 미확정이므로 상태를 CLOSED로 변경하지 않는다.
- 네 번째 세션에서도 운용자가 지연을 보고해 중단한 누적 19회차를 삭제하도록
  요청했다. `20261111_020821_166176_free`는 약 29.36초의 불완전 평가 구간이며
  요청한 해당 폴더만 삭제했다. `deleted_trial_events.json`(네 번째 세션)에
  이력을 남겼다. 이후 19·20회차를 대체 수집해 FREE 20회를 완료했지만 지연
  원인이나 제어 코드가 해결된 것으로 간주하지 않는다.
- 에이전트는 로봇 이동·zero-set·추가 센서 수집을 실행하지 않았다.

- 운용자가 20회 수집 후 검토 결과를 보고 기존 6·16·20회차 삭제와 대체 3회
  수집을 요청했다. 저장 자체는 완료됐으나 실제 판정 계산 간격이 20 ms를
  초과해 세 모델의 판정 규칙 검증이 `INCOMPLETE`였다. 규칙 위반은 발견되지
  않았으며 이 결과만으로 teleop 지연의 원인을 확정하지 않는다.
- 해당 세션에서 `20261111_070810_420207_ramp`(6회차),
  `20261111_072344_722618_ramp`(16회차),
  `20261111_072542_629282_ramp`(20회차)의 원본·회차별 결과 폴더만 삭제했다.
  최대 계산 간격은 각각 26.829/26.912/44.774 ms였다. 제외 기준은 계산 간격이며
  접촉 검출 힘이나 모델 오차가 아니다. 모델 미검출만으로 회차를 제외하지 않는다.
- 남은 17회 원본의 파일 SHA-256이 변경되지 않았음을 확인했다. 집계는 물리
  실험 17회·모델별 결과 51행으로 갱신했다. 삭제·선정 근거는 해당 세션의

- GUI 완료 개수 기준으로 대체 기록은 18·19·20으로 표시된다. 기존 회차 번호를
  변경하지 않았으므로 최종 분석은 표시 번호 대신 고유한 시간별 폴더 ID를 쓴다.
  기존 7회차 제외 원본은 이번 삭제 대상이 아니며 보관 상태를 유지한다.
- 재수집 데이터는 아직 없다. 제어 코드는 수정하지 않았고 하드웨어 조작이나
  데이터 수집을 실행하지 않았다. 최종 결과에는 계산 간격 기준으로 3회를
  삭제·대체한 선정 조건을 명시한다.

## 최종 점증 가압 20회 분석의 입력 시각 불일치

- 운용자가 위 3회를 대체 수집한 뒤, 에이전트는 확정 RAMP 20회의 실제 계산 로그와
  외부 F/T 원본을 읽기 전용으로 대조했다. 20 ms를 초과한 계산 간격은 0회였지만
  로봇 상태와 손목 F/T header 차이가 3 ms를 넘은 tick은 292개였다.
  실제 차이는 3.016~14.169 ms였다. PC–SBC 시계 오차와 수신·처리 지연 중
  어느 원인이 기여했는지는 이 분석으로 확정하지 않았다.
- `ComparisonEngine.step()`은 이 경우 `UNSYNCHRONIZED`를 출력하고 공통
  history와 detector를 초기화한다. 선택된 17개 시행에서 CONTACT 상태 중
  초기화가 모델별 85회 발생했다. 세 모델이 같은 입력을 사용하므로 서로 다른
  물리 사건 255개로 세지 않는다. 이후 `WARMUP` 구간도 기록돼 있다.
- 첫 검출 직전 250 ms에 재준비가 있는 시행도 기존 모델 기준 5개다.
  검출 시 외부 하중은 최초 출력의 관측 결과로 보고하고 모델 단독 문턱이나
  안정적인 접촉 유지 성능으로 확대하지 않는다. 관측 유효 tick의 ON/OFF·hold
  검사는 PASS이나 실시간 주기 및 입력 유효성의 전면 PASS는 아니다.
- 결과: `data/three_model_comparison/evaluation_20261111_free20_ramp20/`의
  `summary.json`, `input_timing.csv`, `ramp_trials.csv`, `detector_transitions.csv`.
  원본은 추가 제외·삭제하지 않았다. 제어·입력 결합 코드를 수정하지 않았고
  하드웨어 동작·추가 수집도 실행하지 않았다.
